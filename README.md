# Restos — Система оценки сотрудников

## Описание системы

**Restos** — Telegram-бот для проведения комплексной оценки сотрудников организаций. Система обеспечивает полный цикл управления: от регистрации и настройки организации до проведения замеров, аналитики и генерации отчётов.

---

## Роли и права доступа

Система поддерживает четыре уровня доступа. Роль определяется двумя независимыми механизмами:
- **Суперпользователь** — флаг `is_bot_administrator` в модели `User`
- **Роль внутри организации** — поле `employee_type_id` в модели `Employee` (связь с `EmployeeType`)

### Матрица прав

| Действие | Суперпользователь | Администратор орг. | Менеджер (invite-only) | Сотрудник |
|---|:---:|:---:|:---:|:---:|
| Создать организацию | ✅ | ❌ | ❌ | ❌ |
| Редактировать организацию | ✅ | ✅ | ❌ | ❌ |
| Переключать организацию | ✅ | ❌ | ❌ | ❌ |
| Пригласить администратора | ✅ | ❌ | ❌ | ❌ |
| Пригласить сотрудника в орг. | ✅ | ✅ | ✅ | ❌ |
| Управлять сотрудниками (CRUD) | ✅ | ✅ | ❌ | ❌ |
| Создать/редактировать критерии | ✅ | ✅ | ❌ | ❌ |
| Создать/редактировать наборы | ✅ | ✅ | ❌ | ❌ |
| Создать/редактировать тип замера | ✅ | ✅ | ❌ | ❌ |
| Провести замер | ✅ | ✅ | ❌ | ❌ |
| Просмотреть свои замеры | ✅ | ✅ | ✅* | ✅* |
| Аналитика | ✅ | ✅ | ❌ | ❌ |
| Экспорт (PDF/Excel) | ✅ | ✅ | ❌ | ❌ |

> \* Доступ к просмотру замеров для Менеджера и Сотрудника ограничен — только те замеры, в которых они участвовали.

### Описание ролей

#### Суперпользователь (`is_bot_administrator = true`)
Главный администратор системы. Единственная роль, не привязанная к конкретной организации.
- Может создавать любые организации
- Может переключаться между организациями
- Может рассылать ссылки-приглашения для получения статуса администратора
- Полный доступ ко всем функциям в любой организации

#### Администратор организации (`employee_type.code = "administrator"`)
Получает статус через приглашение суперпользователя. Привязан к одной организации.
- Редактирует организацию, управляет сотрудниками, критериями, наборами
- Проводит замеры и просматривает аналитику
- Может приглашать новых сотрудников/менеджеров по ссылке в свою организацию
- **Не может** создавать новые организации и переключаться между ними

#### Менеджер (`employee_type.code = "manager"`)
Промежуточная роль — может только приглашать людей по ссылке в свою организацию.
- Генерирует ссылку-приглашение для своей организации
- Просматривает свои замеры (в которых участвовал)
- **Не имеет** доступа к управлению, аналитике, критериям

#### Сотрудник (`employee_type.code = "employee"`)
Базовая роль. Вступает в организацию только по ссылке-приглашению.
- Может просматривать замеры, в которых участвовал
- **Не имеет** доступа к управлению и аналитике

## Флоу регистрации и входа

```
Пользователь → /start
        │
        ├── [Есть код приглашения в команде: /start <code>]
        │         │
        │         ├── Тип приглашения "admin"
        │         │     └── Устанавливается is_bot_administrator=true
        │         │         └── Пользователь становится Суперпользователем
        │         │
        │         └── Тип приглашения "employee"
        │               └── Создаётся запись Employee в указанной организации
        │                   └── Переход в Главное меню
        │
        └── [Нет кода приглашения]
                  │
                  ├── Пользователь уже в организации → Главное меню
                  │
                  └── Пользователь не в организации
                        └── Экран помощи / ожидание приглашения
```

### Логика организационного контекста

- **Суперпользователь**: видит все организации, может переключаться между ними через кнопку в меню
- **Все остальные**: работают только в своей организации (контекст организации определяется автоматически при входе, переключение недоступно)

## Главное меню и доступные разделы

```
Главное меню (greeting)
    │
    ├── Панель администратора 🛠  [admin/superuser]
    │     ├── Настройка критериев ────────→ CriterionDialog / CriterionSetDialog
    │     ├── Управление сотрудниками ───→ EmployeeDialog
    │     ├── Организации ───────────────→ OrganizationDialog
    │     ├── Замеры (создать / удалить) → EvaluationDialog
    │     └── Аналитика ─────────────────→ AnalyticsDialog
    │
    ├── Моё меню 📂  [все роли]
    │     ├── Мои замеры ────────────────→ Просмотр своих результатов
    │     └── Пройти замер ──────────────→ EvaluationDialog (admin/superuser)
    │
    ├── Пригласить в организацию 🔗  [admin/manager/superuser]
    ├── Пригласить администратора 👑  [superuser]
    ├── Переключить организацию 🔄  [superuser]
    └── Помощь ❓  [все]
```

> Структура соответствует дизайн-схеме: две основные ветки — «Панель администратора» (левая) и «Моё меню» (правая).

## Детальные State Flow по диалогам

### OrganizationDialog
```
[Суперпользователь]
  select_organization_to_edit
        └── edit_menu
              ├── name_input → code_input → address_input → phone_input → confirm
              ├── manage_employees
              │     └── invite_employee  (генерация ссылки для сотрудника/менеджера)
              └── [создать новую] → name_input → ... → confirm

[Администратор]
  edit_menu (только своя организация, без create)
        ├── name_input → ... → confirm
        └── manage_employees → invite_employee
```

### EmployeeDialog
```
select_organization (только суперпользователь; для остальных — автоматически)
      └── select_employee_to_edit
                └── edit_menu
                      └── full_name_input → position_input → phone_input → confirm → add_more
```

### CriterionDialog
```
select_organization (только суперпользователь)
      └── select_criterion
                ├── [существующий] → edit_menu
                └── [новый] → select_value_type → select_is_required
                                  → name_input → code_input → description_input → confirm → add_more
```

### CriterionSetDialog
```
select_organization (только суперпользователь)
      └── select_set
                ├── [существующий] → edit_menu
                └── [новый] → name_input → description_input → select_criteria → set_default → confirm
                             [импорт] → upload_excel
```

### EvaluationDialog
```
select_evaluation_type
      │   └── [создать тип] → evaluation_type_name_input → code_input → description_input → confirm
      │
select_organization (только суперпользователь)
      │
select_filled_by_employee
      │
select_evaluated_employee
      │
select_criterion_set
      │   └── combine_criterion_sets  (опционально)
      │
select_evaluation_method
      │   ├── [бот] → question_loop → answer_question / answer_text / answer_number
      │   │                                └── add_comment (опционально)
      │   └── [веб-форма] → отправка ссылки сотруднику

### AnalyticsDialog
```
select_organization (только суперпользователь)
      └── select_analytics_type
                ├── Статистика по критериям
                │     └── select_criteria → select_employees → select_date_range
                │                               └── display_results → export_results

## Система приглашений

Реализована через Redis с TTL. Два типа приглашений:

| Тип | Кто создаёт | Что происходит при активации |
|---|---|---|
| `admin` | Суперпользователь | Пользователю устанавливается `is_bot_administrator=true` |
| `employee` | Суперпользователь / Администратор / Менеджер | Пользователь создаётся как `Employee` в указанной организации |

- Ссылка действует **7 дней**, однократного использования
- Формат: `/start <code>` (глубокая ссылка Telegram)

---

## Организационный контекст

Каждая операция привязана к конкретной организации. Контекст хранится в `middleware_data["organization"]`.

- При старте (`/start`) контекст организации определяется автоматически по `telegram_id` пользователя
- **Суперпользователь** видит список всех организаций в начале каждого управляющего диалога
- **Все остальные** автоматически помещаются в свою организацию — диалог выбора организации им не показывается

## Быстрый старт

### Первоначальная настройка (Суперпользователь)

1. Создать организацию: Организации → Создать организацию
2. Добавить администратора: Сотрудники → Пригласить администратора (из меню суперпользователя)  
   — или добавить сотрудников напрямую через меню Сотрудники
3. Создать типы замеров: Критерии и наборы → Типы замеров
4. Создать критерии: Критерии и наборы → Критерии
5. Сформировать наборы критериев: Критерии и наборы → Наборы

### Приглашение команды (Суперпользователь / Администратор)

- **Пригласить администратора** (только суперпользователь): Сотрудники → Пригласить администратора  
  → ссылка вида `t.me/bot?start=<code>` → пользователь получает статус `is_bot_administrator`
- **Пригласить сотрудника**: Организации → [выбрать орг.] → Управление сотрудниками → Пригласить  
  → ссылка привязана к конкретной организации

### Проведение замера

1. Оценки → Сделать замер
2. Выбрать тип оценки (или создать новый)
3. Выбрать кто заполняет и кого оценивают
4. Выбрать набор критериев (или скомбинировать несколько)
5. Выбрать метод: ответить в боте или отправить веб-форму сотруднику
6. Получить отчёт (PDF / Excel)

## Технические особенности

### Модели данных

| Модель | Ключевые поля |
|---|---|
| `User` | `telegram_id`, `is_bot_administrator`, `is_verified` |
| `Employee` | `telegram_id`, `organization_id`, `employee_type_id`, `position`, `meta` |
| `EmployeeType` | `name`, `code` (`employee` / `manager` / `administrator`) |
| `Organization` | `name`, `code`, `address`, `phone`, `meta` |
| `Evaluation` | `organization_id`, `filled_by_employee_id`, `evaluated_employee_id`, `evaluation_type_id` |
| `Criterion` | `name`, `code`, `value_type` (boolean / string / number) |
| `CriterionSet` | `name`, связан с критериями, `is_default` |

### Стек технологий

- **Bot framework**: aiogram 3 + aiogram-dialog
- **База данных**: PostgreSQL (asyncpg + SQLAlchemy)
- **Кэш / хранилище сессий**: Redis
- **Миграции**: Alembic
- **DI**: dependency-injector
- **ИИ-ассистент**: интеграция с внешними AI-API (анализ на русском языке)
- **Экспорт**: PDF (reportlab / weasyprint), Excel (openpyxl)

### Генерация отчётов

- **PDF**: форматированный отчёт с результатами замера
- **Excel**: табличные данные для внешнего анализа
- Экспорт доступен как сразу после замера, так и из раздела аналитики
