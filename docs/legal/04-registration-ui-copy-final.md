**Privacy:** `restos-privacy-2026-08-10-v1`  
**PD consent:** `restos-pd-consent-2026-08-10-v1`  
**Terms:** `restos-terms-2026-08-10-v1`  
**Authorization SMS consent:** `restos-auth-sms-consent-2026-08-10-v1`

## 1. Регистрация: экран телефона

Перед кнопкой **«Получить код»** разместить два независимых, пустых по умолчанию элемента подтверждения.

### Согласие на обработку персональных данных

**Checkbox (обязателен для отправки регистрационного OTP):**

> Я даю согласие на обработку моих персональных данных для регистрации, аутентификации и обеспечения безопасности RestOS в соответствии с Согласием на обработку персональных данных.

Слова **«Согласием на обработку персональных данных»** — ссылка на `/personal-data.html`.

### Согласие на авторизационное SMS

**Checkbox (обязателен только для отправки SMS):**

> Я согласен(на) получить сервисное SMS с одноразовым кодом для подтверждения номера телефона. Рекламные и маркетинговые SMS RestOS не отправляет.

Оба checkbox должны быть `false` по умолчанию. Никакого marketing consent не добавлять.

Если SMS-согласие не отмечено, кнопка «Получить код» недоступна. Рядом можно показать нейтральную подсказку:

> Для регистрации по номеру телефона требуется одноразовый код из SMS.

## 2. Регистрация: экран создания Account

Под полями пароля, непосредственно перед кнопкой **«Создать аккаунт»**:

> Нажимая «Создать аккаунт», вы принимаете Условия использования RestOS и подтверждаете, что ознакомились с Политикой конфиденциальности.

**«Условия использования RestOS»** → `/terms.html`  
**«Политикой конфиденциальности»** → `/privacy.html`

Согласие на обработку персональных данных в этот текст не объединять: оно уже предоставлено отдельным действием.

## 3. Invitation signup нового пользователя

Использовать тот же набор:

- отдельное PD consent на этапе телефона;
- отдельное authorization SMS consent;
- Terms + Privacy notice перед созданием Account.

Legal acceptance context для нового Account: `account_registration`.

## 4. Приглашение существующего Account

Новое согласие на обработку персональных данных и новый Terms acceptance автоматически не создавать только из-за принятия приглашения. Invitation acceptance остается отдельным бизнес-событием.

Если для новых функций организации потребуется отдельное правовое основание, это решается отдельным product/legal изменением.

## 5. Password recovery

Перед отправкой recovery OTP требуется только отдельное согласие на получение соответствующего сервисного SMS:

> Я согласен(на) получить сервисное SMS с одноразовым кодом для восстановления доступа к RestOS.

Новое PD consent и Terms acceptance при восстановлении пароля не создаются.

## 6. Login

На обычном login достаточно ссылок на Политику конфиденциальности и Условия использования. Новые consent events не создаются.

## 7. FIO label

В Account creation использовать label:

> ФИО

Backend/API поле `display_name` не переименовывать. Не разбивать ФИО на три поля в этом релизе.
