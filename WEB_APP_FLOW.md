## 🔐 Роли пользователей

### 1. Супер-админ (TGBOT_ADMIN_IDS)
- Полный доступ ко всем функциям
- Может управлять любой организацией
- Всегда имеет права администратора

### 2. Администратор организации (employee_type_code = "administrator")
- Полный доступ к своей организации
- Может управлять сотрудниками, критериями, наборами
- Может создавать оценки для всех сотрудников
- Доступ к аналитике

### 3. Обычный сотрудник (employee_type_code = "employee")
- Может создавать оценки для других сотрудников
- Не может редактировать организацию, критерии, наборы
- Ограниченный доступ к аналитике (только свои оценки)

### 4. Наблюдатель (employee_type_code = "observer")
- Только чтение данных
- Не может создавать/редактировать

## 🏠 Главная страница (/)

### Назначение
Главное меню приложения с навигацией по всем разделам.

### Flow при загрузке

```
1. Загрузка страницы
   ↓
2. Получить данные текущего пользователя
   API: GET /api/v1/users/{telegram_id}?chat_id={chat_id}
   ↓
3. Получить организацию пользователя
   API: GET /api/v1/organizations?telegram_id={telegram_id}
   ↓
4. Если организации нет → Redirect на /organizations (создание)
   ↓
5. Получить роль пользователя в организации
   API: GET /api/v1/employees/telegram/{telegram_id}?organization_id={id}
   ↓
6. Отобразить меню в зависимости от роли
```

### Доступ

✅ Администратор организации  
❌ Обычный сотрудник

### Flow: Список организаций

```
1. Загрузка /organizations
   ↓
2. Проверка прав доступа
   API: GET /api/v1/employees/telegram/{telegram_id}?organization_id={id}
   if employee.meta.employee_type_code !== 'administrator' → 403 Forbidden
   ↓
3. Получить список организаций
   API: GET /api/v1/organizations?telegram_id={telegram_id}
   ↓
4. Отобразить список с кнопками:
   - Просмотр/Редактирование
   - Управление сотрудниками
   - Создать новую организацию

### Flow: Создание организации

```
1. Клик на "Создать организацию"
   ↓
2. Форма ввода:
   - Название (обязательно)
   - Код (обязательно, уникальный)
   - Адрес (опционально)
   - Телефон (опционально)
   ↓
3. Валидация на фронте:
   - Название: не пустое
   - Код: заглавные буквы, без пробелов
   ↓
4. Отправка данных
   API: POST /api/v1/organizations
   Body: {
     "name": "ООО Техно",
     "code": "TECHNO",
     "address": "г. Москва",
     "phone": "+7 (999) 123-45-67"
   }
   ↓
5. Получение ответа с ID организации
   ↓
6. Автоматическое создание администратора
   API: POST /api/v1/employees
   Body: {
     "organization_id": 1,
     "employee_type_id": 3,  // administrator
     "full_name": "Иван Иванов",
     "telegram_id": 123456789
   }
   ↓
7. Redirect на /organizations/{id} или предложить добавить сотрудников
```

```
1. Загрузка /employees
   ↓

   ↓

   ↓
4. Получить сотрудников организации
   API: GET /api/v1/employees?organization_id={id}&include_deleted=false
   ↓
5. Отобразить список с фильтрами:
   - По должности
   - По типу (администратор/сотрудник/наблюдатель)

```
1. Переход на /employees/new
   ↓
2. Форма создания:
   Шаг 1: Основная информация
   - ФИО (обязательно)
   - Должность (опционально)
   - Телефон (опционально)
   - Тип сотрудника (select)
   
   Шаг 2: Связь с Telegram (опционально)
   - Telegram ID (если известен)
   - ИЛИ Создать приглашение
   ↓
3. Отправка данных
   API: POST /api/v1/employees
   ↓
4. Если нужно приглашение:
   API: POST /api/v1/invitations
   ↓
5. Redirect на /employees/{id} с отображением приглашения
```

## 🔑 Ключевые моменты реализации

### 1. Управление состоянием

На фронтенде использовать state management (например, Zustand, Redux):

```javascript
// Пример структуры state
{
  user: {
    telegram_id: 123456789,
    organization_id: 1,
    employee_id: 5,
    role: 'administrator',  // 'administrator', 'employee', 'observer'
    is_admin: true  // супер-админ из TGBOT_ADMIN_IDS
  },
  organization: {
    id: 1,
    name: "ООО Техно",
    code: "TECHNO",
    ...
  },
  evaluationDraft: {
    // Временное хранение данных при создании оценки
    evaluation_type_id: 1,
    evaluated_employee_id: 2,
    criterion_set_id: 1,
    current_question_index: 2,
    answers: {...},
    comments: {...}
  }
}
```

### 2. Проверка прав доступа

Создать helper функцию для проверки прав:

```javascript
function checkPermission(user, action) {
  // Супер-админ может всё
  if (user.is_admin) return true;
  
  // Администратор организации
  if (user.role === 'administrator') {
    return ['manage_org', 'manage_employees', 'manage_criteria', 
            'manage_sets', 'create_evaluation', 'view_analytics'].includes(action);
  }
  
  // Обычный сотрудник
  if (user.role === 'employee') {
    return ['create_evaluation', 'view_my_evaluations'].includes(action);
  }
  
  // Наблюдатель
  if (user.role === 'observer') {
    return ['view_evaluations', 'view_analytics'].includes(action);
  }
  
  return false;
}
```

### 3. Оптимизация запросов

- Использовать кэширование для часто запрашиваемых данных
- Prefetch данные для следующих шагов
- Pagination для больших списков
- Debounce для поиска и фильтров

### 4. Offline поддержка

- Сохранять черновики оценок в localStorage
- Показывать кэшированные данные при отсутствии сети
- Синхронизировать при восстановлении связи
